# ZafaRix87 — стартовый шаблон проекта

Этот репозиторий подготовлен как **базовый каркас** для нового проекта.
Сейчас здесь нет бизнес-логики — только структура, с которой удобно стартовать и расти.

## Быстрый обзор структуры

```text
.
├── .github/workflows/   # CI-пайплайны (проверки на PR и main)
├── docs/                # документация по архитектуре и решениям
├── scripts/             # служебные скрипты (локальный запуск, утилиты)
├── src/                 # исходный код приложения
├── tests/               # автотесты
├── CONTRIBUTING.md      # правила для участников
└── README.md            # этот файл
```

## Что важно знать новичку

1. **Код живёт в `src/`**, тесты — в `tests/`.
2. Любая новая функциональность должна сопровождаться:
   - кратким описанием в PR;
   - тестами или объяснением, почему тесты пока не добавлены;
   - обновлением документации в `docs/`, если меняется архитектура/контракты.
3. Избегай больших «смешанных» PR: лучше маленькие, атомарные изменения.

## Рекомендуемый порядок старта

1. Выбери стек (например, Python/FastAPI, Node.js/Nest, Go, Rust).
2. Добавь минимальную исполняемую точку входа в `src/`.
3. Добавь 2–3 smoke-теста в `tests/`.
4. Подключи линтер и форматтер.
5. Включи CI-проверки в `.github/workflows/`.

## Подсказки, которые стоит изучить дальше

- `CONTRIBUTING.md` — базовые правила разработки и чеклист для PR.
- `docs/` — сюда стоит добавить:
  - `architecture.md` (границы модулей и зависимости),
  - `decisions/` (архитектурные решения, ADR),
  - `runbook.md` (как запускать и диагностировать).

## Минимальный чеклист перед первым релизом

- [ ] Есть команда локального запуска.
- [ ] Есть команда запуска тестов.
- [ ] Есть линтер/форматтер.
- [ ] Есть CI-пайплайн на pull request.
- [ ] Есть базовый мониторинг/логирование.
